# Космослов — Архітектура Свідка: інструкція з упровадження

Версія схеми: `attestation_witness.v0`
Статус: інструкція до пререєстрації COSMOSLOV-001. Не є PASS, не є валідацією.

---

## 0. Засадничий принцип

> **Атестація — це не текст. Це координата в запечатаному артефакті.**

Цитата ніколи не зберігається як твердження. Вона обчислюється читанням
запечатаного файлу за координатою. Наслідок: модель, що пропонує координату,
може бути скільки завгодно ненадійною — перевірка не залежить від її чесності.

Термін «свідок» (witness) вжито у значенні текстології: джерело, що засвідчує
читання і яке можна повторно оглянути.

---

## 1. Три регістри

Запис НІКОЛИ не змішує регістри в одному полі. Регістр — це колонка, і він
завжди присутній в експорті та в UI.

| Регістр | Що це | Свідок | Приклад |
| --- | --- | --- | --- |
| `attested` | засвідчено у власному запечатаному корпусі | координата в артефакті | `ansible` у Rocannon's World, байти 214880–215040 |
| `external` | спирається на зовнішній авторитет | координата в архівованому знімку | HD SF, запис 16, знімок від 2026-09-06 |
| `proposed` | українська пропозиція за моделлю Грінченка | **немає за визначенням** | «Миттєвісник» |

Правило: `proposed` не може бути підвищений до `attested` інакше, ніж через
появу справжнього свідка. Автоматичне підвищення заборонене назавжди.

## 2. Примітив свідка

```
witness = (cts_urn, artifact_sha256, byte_start, byte_len, window_sha256)
```

| Поле | Призначення |
| --- | --- |
| `cts_urn` | канонічна адреса пасажу за CTS URN (стандарт CITE) |
| `artifact_sha256` | хеш файлу; мусить бути в запечатаному маніфесті Exometric |
| `byte_start` | зміщення від початку файлу в БАЙТАХ (не символах) |
| `byte_len` | довжина вікна в байтах |
| `window_sha256` | хеш саме цих байтів |

Байти, не символи: символьні зміщення залежать від кодування й нормалізації
Unicode. Байти — ні.

### Верифікатор — це весь критик

```python
def verify_witness(w, seal, term):
    if w.artifact_sha256 not in seal.hashes:      return REJECT("unsealed_artifact")
    path = seal.path_for(w.artifact_sha256)
    if file_sha256(path) != w.artifact_sha256:    return REJECT("artifact_drift")
    with open(path, "rb") as f:
        f.seek(w.byte_start)
        window = f.read(w.byte_len)
    if len(window) != w.byte_len:                 return REJECT("short_read")
    if sha256(window) != w.window_sha256:         return REJECT("window_mismatch")
    text = window.decode("utf-8")
    if term.lower() not in text.lower():          return REJECT("term_absent")
    return ACCEPT(quote=text)
```

П'ять перевірок. Усі бінарні. Жодних ваг, жодних порогів, жодного
часткового заліку. Це замінює `KarpathyCritic.evaluate_candidate` цілком.

## 3. Шари

### Шар 0 — Ворота автентичності набуття

Жоден текст не входить у корпус без чека набуття.

```json
{
  "work_slug": "the-time-machine",
  "edition_id": "gutenberg:35",
  "source_url": "https://www.gutenberg.org/files/35/35-0.txt",
  "http_status": 200,
  "fetched_at_utc": "2026-09-06T12:00:00Z",
  "raw_sha256": "<хеш СИРОГО завантаження, до очищення>",
  "raw_bytes": 184958,
  "clean_sha256": "<хеш після очищення>",
  "transform_id": "clean_gutenberg_text",
  "transform_sha256": "<хеш коду функції очищення>",
  "rights": "public_domain",
  "acquisition_class": "verified"
}
```

`transform_sha256` обов'язковий: без нього очищення невідтворюване, і
байтові зміщення не мають сенсу після зміни коду очищення.

Fail-closed: немає чека → `acquisition_class: unsourced` → у дослідження не
потрапляє. Ніколи.

### Шар 1 — Печатка Exometric

Запечатувати ЧЕКИ НАБУТТЯ І ОЧИЩЕНІ ТЕКСТИ РАЗОМ, одним маніфестом.

Пін runtime: `E0406ED4C0A43858505DB138B069DAD1F2031C26B9EAB0F3E0823485D8EB3CBD`
Перевіряти SHA до і після ізольованого імпорту (правило моста).

Обов'язково за розділом 5 моделі довіри: звіряти `head_chain_hash` із
git-закоміченим чеком циклу. Внутрішньої верифікації НЕ ДОСТАТНЬО —
самоузгоджене обрізання проходить її за побудовою.

**Застереження, яке коштувало б усієї роботи.** Печатка гарантує цілісність
від моменту запечатування, а не автентичність у момент набуття. Запечатаний
фальсифікат отримує бездоганний PASS — це перевірено на цьому корпусі
2026-09-06: файл R.U.R. із кирилічними к/а в чеському `člověka` отримав
`status: PASS` першим записом ланцюга. Тому Шар 0 передує Шару 1 завжди.

### Шар 2 — Пререєстрація Manifold

Кожен прогін = документ до запуску, за наявним форматом:
`Purpose / Authorized Changes / Prohibited Changes / Acceptance / Boundary`.

## 4. Схема БД

Обмеження CHECK робить фальсифікацію порушенням цілісності на рівні СУБД:
записати `attested` без повного свідка технічно неможливо.

```sql
CREATE TABLE acquisition_receipts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  work_slug TEXT NOT NULL,
  edition_id TEXT NOT NULL,
  source_url TEXT,
  http_status INTEGER,
  fetched_at_utc TEXT NOT NULL,
  raw_sha256 TEXT NOT NULL,
  raw_bytes INTEGER NOT NULL,
  clean_sha256 TEXT NOT NULL,
  transform_id TEXT NOT NULL,
  transform_sha256 TEXT NOT NULL,
  rights TEXT NOT NULL,
  acquisition_class TEXT NOT NULL
    CHECK (acquisition_class IN ('verified','synthetic','unsourced')),
  UNIQUE (work_slug, edition_id)
);

CREATE TABLE attestations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  term_id INTEGER NOT NULL,
  work_id INTEGER,
  year INTEGER,
  register TEXT NOT NULL
    CHECK (register IN ('attested','external','proposed')),

  -- свідок регістру attested
  cts_urn TEXT,
  artifact_sha256 TEXT,
  byte_start INTEGER,
  byte_len INTEGER,
  window_sha256 TEXT,

  -- свідок регістру external
  authority TEXT,
  authority_url TEXT,
  authority_snapshot_sha256 TEXT,
  retrieved_at_utc TEXT,

  verified_at_utc TEXT,
  verifier_version TEXT,
  proposed_by_model TEXT,

  FOREIGN KEY (term_id) REFERENCES terms(id) ON DELETE CASCADE,

  CHECK (
    (register = 'attested'
      AND cts_urn IS NOT NULL AND artifact_sha256 IS NOT NULL
      AND byte_start IS NOT NULL AND byte_len IS NOT NULL
      AND window_sha256 IS NOT NULL)
    OR (register = 'external'
      AND authority IS NOT NULL AND authority_snapshot_sha256 IS NOT NULL)
    OR (register = 'proposed'
      AND cts_urn IS NULL AND artifact_sha256 IS NULL)
  )
);
```

**Колонки з текстом цитати не існує.** Цитата рендериться функцією
`render_quote(attestation)`, що відкриває запечатаний файл і читає вікно.
Єдине джерело істини — корпус, не БД.

Поле `terms.first_attestation_year` ВИДАЛЯЄТЬСЯ. Замінюється поданням:

```sql
CREATE VIEW earliest_attestation AS
SELECT term_id,
       MIN(year)                     AS earliest_year,
       COUNT(*)                      AS witness_count,
       'corpus_seal_relative'        AS claim_type
FROM attestations
WHERE register = 'attested' AND verified_at_utc IS NOT NULL
GROUP BY term_id;
```

Формулювання твердження в кожному експорті — дослівно:
«найраніша засвідчена поява в корпусі з печаткою `<head_chain_hash>`»,
ніколи «перша поява».

## 5. Перевернутий цикл автодослідження

Було: LLM постачає і цитату, і переклад. Стало — три ролі, розділені:

```
1. ПРОПОЗИЦІЯ   LLM читає вікна тексту й називає КАНДИДАТІВ-ТЕРМІНІВ.
                Цитат не постачає. Може помилятися вільно.

2. ЛОКАЛІЗАЦІЯ  Детермінований пошук по ПОВНОМУ тексту (search_term_context)
                знаходить усі входження й обчислює справжні координати.
                Джерело істини — корпус.

3. ДЕРИВАЦІЯ    LLM отримує ВЖЕ ЗНАЙДЕНУ справжню цитату і робить лише
                українську морфологічну пропозицію. Регістр proposed.
```

Скасувати `raw_text[:1800]` — обробляти повний текст вікнами з перекриттям
(перекриття ≥ найдовшого очікуваного терміна, інакше термін на межі вікон
загубиться).

Скасувати позначення твору `analyzed` після одного терміна. Твір опрацьовано
тоді, коли пройдено всі вікна.

Справжній loss циклу:
```
loss = 1 - (verified_witnesses / proposed_candidates)
```

### 5.1 Структурні зони (виявлено на прогоні 2026-09-06)

Перше входження терміна у файл часто лежить у службовій зоні, а не в
оповіді. Перевірено: `Morlock` у The Time Machine має перше входження на
байті 484 — це ЗМІСТ, не текст. Свідок при цьому верифікується бездоганно,
бо байти справжні; хибним є науковий статус пасажу.

Тому кожен артефакт мусить мати карту зон:

```json
{
  "zones": [
    {"kind": "front_matter", "byte_start": 0,    "byte_end": 2100},
    {"kind": "toc",          "byte_start": 2100, "byte_end": 3400},
    {"kind": "body",         "byte_start": 3400, "byte_end": 184100},
    {"kind": "back_matter",  "byte_start": 184100,"byte_end": 184958}
  ]
}
```

Правила:
- Для `earliest_attestation` враховуються ТІЛЬКИ свідки із зони `body`.
- Свідок із `toc`/`front_matter` зберігається, але з позначкою
  `zone: toc` і не бере участі в датуванні.
- Карта зон входить у запечатаний маніфест нарівні з текстом: зміна меж зон
  змінює наукове твердження, отже мусить бути під печаткою.

Це той випадок, коли технічна перевірка проходить, а наукова — ні. Обидві
потрібні.

## 6. Незалежний переобрахунок (N-version)

За зразком `exometric_lineage_independent.py` (`imports_exometric: false`).

Другий верифікатор, написаний незалежно, лише на stdlib, що НЕ імпортує
основний. Обидва мусять дати той самий вердикт по кожному свідку.
Розбіжність = зупинка циклу і ручний розгляд, ніколи не автоприйняття.

## 7. Калібрування за зовнішнім еталоном

HD SF (`sfdictionary.com`) — похідна від OED Science Fiction Citations
Project, має скани сторінок. Використовується як незалежний валідаційний
набір, не як джерело для копіювання.

Процедура: прогнати конвеєр на термінах, наявних у HD SF; порівняти власну
`earliest_year` з їхньою.

| Результат | Тлумачення |
| --- | --- |
| збіг року і твору | найвища довіра |
| наша раніша | кандидат на антедатування — перевірити вручну, це знахідка |
| наша пізніша | корпусу бракує тексту → завести як `external`, позначити прогалину |
| твір різний | помилка атрибуції, розібрати вручну |

Метрика якості конвеєра = precision/recall проти HD SF. Це і є
«перевірено узгоджено валідовано» в операційному сенсі.

Очікувати розбіжностей — норма: OED3 антедатував ~60% власних датувань при
переході на цифрові корпуси. Розбіжність не є дефектом системи.

## 8. Порядок упровадження

| Крок | Дія | Готовність |
| --- | --- | --- |
| 1 | Карантин: 6 синтетичних файлів → `acquisition_class: synthetic`, вилучити з усіх вибірок | жоден дослідницький запит їх не бачить |
| 2 | Таблиця `acquisition_receipts`; ретро-набуття 11 ґутенберзьких творів; звірити `raw_sha256` повторним завантаженням | 11 чеків `verified`, розбіжностей 0 |
| 3 | Таблиця `attestations` з CHECK; видалити `terms.first_attestation_year`; подання `earliest_attestation` | спроба вставити `attested` без свідка падає на CHECK |
| 4 | `verify_witness` + незалежний верифікатор; замінити `KarpathyCritic` | обидва згодні на 100% тестових свідків |
| 5 | Перевернути цикл (пропозиція / локалізація / деривація), зняти зріз 1800 | покриття корпусу 100%, не 0.7% |
| 6 | Печатка Exometric над (чеки + тексти + ця інструкція); head у git | `head_chain_hash` у чеку циклу |
| 7 | Пререєстрація COSMOSLOV-001 | документ до запуску, не після |
| 8 | Калібрування за HD SF | таблиця розбіжностей |
| 9 | Клас B (культура, кіно) — окремим циклом, власна пререєстрація | не починати до кроку 8 |

Кроки 1–5 не потребують ані Manifold, ані Exometric. Кроки 6–7 роблять
результат незаперечним.

## 9. Заборонене (нормативно)

1. LLM не постачає цитат. Ніколи. Ні в якому режимі.
2. Немає свідка → немає запису. Часткового заліку не існує.
3. Синтетичні тексти не живлять атестацію за жодних умов.
4. Посилання на Грінченка без звірки з оцифрованим джерелом позначається
   `unverified`. Промпт не просить модель називати том і сторінку.
5. `proposed` не підвищується до `attested` автоматично.
6. Поріг прийняття не змінюється після прогону. Тільки нова пререєстрація.
7. Твердження «перша поява» не вживається. Тільки «найраніша в корпусі з
   печаткою H».
8. Печатка Exometric не є доказом наукової правильності, лише цілісності
   сліду (модель довіри, розділ 4.4).

## 10. Критерії приймання

- Кожен `attested` проходить обидва незалежні верифікатори.
- Кожна цитата в експорті відтворюється читанням запечатаного файлу.
- Спроба вставити `attested` без повного свідка падає на CHECK.
- Фальсифікований кандидат (координата в нікуди) відхиляється; є регресійний
  тест саме на цей випадок, а не на кандидата з відсутніми полями.
- `'12345'` не проходить морфологічну перевірку; `'мислитель'` проходить.
- Покриття корпусу = 100% байтів верифікованих творів.
- `head_chain_hash` збігається з git-закоміченим чеком.
- Жоден свідок із зони `toc`/`front_matter` не впливає на датування.

### Перевірено на цьому корпусі 2026-09-06

| Перевірка | Результат |
| --- | --- |
| CHECK відхиляє `attested` без свідка | ВІДХИЛЕНО |
| CHECK відхиляє `attested` з частковим свідком | ВІДХИЛЕНО |
| CHECK відхиляє `proposed`, що вдає свідка | ВІДХИЛЕНО |
| Свідок на справжньому тексті (The Time Machine) | ACCEPT, цитата обчислена з файлу |
| Зсув координати на 1 байт | REJECT `window_mismatch` |
| Вигадана координата | REJECT `short_read` |
| Підмінений хеш вікна | REJECT `window_mismatch` |
| Exometric: чиста печатка / підміна / перестановка | PASS / FAIL / FAIL |

Термінальний результат — WATCH-only свідчення. PASS продукту, валідація
сигналу чи дозвіл на публікацію з нього не виводяться.
