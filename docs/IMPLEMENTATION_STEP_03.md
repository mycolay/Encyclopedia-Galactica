# Крок 03 — відновлювана черга та покриття корпусу

Дата: 2026-09-06. Статус: реалізовано інфраструктуру виділення кандидатів;
предметний прогін перевірив планування, а не модельний аналіз корпусу.

## Знайдені дефекти й рішення

Старий цикл починав кожен запуск із перших вікон; початкове байтове
зміщення застосовувалося до символьного рядка. Після першого записаного
терміна цикл повертався, не зберігши чергу решти кандидатів. Клієнт LLM
перетворював транспортні й JSON-помилки на порожній список кандидатів.

Додано окремий відновлюваний етап extraction із власною SQLite. Він
зберігає всі повернуті кандидати та точні байтові діапазони фрагментів,
не створює передчасно статей. Помилки клієнта тепер передаються виконавцю.
Коректний порожній список відрізняється від помилки.

Реалізовано атомарну видачу завдань, lease/token, повернення простроченого
завдання, стелю трьох спроб і журнал подій. Покриття — об'єднання успішно
завершених діапазонів без подвійного рахування перекриття. Результат і
done фіксуються однією транзакцією. Нові хеші джерела, карти або профілю
створюють окремий план; історія не стирається.

## Перевірки та прогін

Виконавець і протокол зафіксовані до прогону: `2e4b929`.
Команда:

```powershell
python scripts/corpus_queue.py plan --queue .benchmarks/corpus-queue-step03-001/queue.db --report .benchmarks/corpus-queue-step03-001/plan.json
```

Результат: 23 плани, 1015 завдань, 7 926 371 цільовий байт, 0 відмов.
Повторний plan дав ідентичний звіт, без дублікатів і скидання стану.
Виконаних модельних фрагментів 0; наукове покриття не заявляється.

Тести: 23 пройшли — 6 нових і 17 попередніх. Нові перевіряють
Unicode/перекриття/хвіст, відновлення через новий екземпляр черги,
кілька body-зон, lease/recovery та відмову старому виконавцю, помилки
й стелю повторів, дрейф джерела/новий план, ідемпотентність, строгий JSON.
Тестові клієнти є фікстурами; їхні результати не перенесені в робочий корпус.

Квитанція: [IMPLEMENTATION_STEP_03_RECEIPT.json](IMPLEMENTATION_STEP_03_RECEIPT.json).
Прогін і черга збережені в `.benchmarks/corpus-queue-step03-001/`.
Квитанція цього кроку містить звичайні хеші, ще не печатку Exometric.
Мережа, GPU й LLM не використовувалися; основна БД і корпус не змінювалися.

## Як продовжувати

Поточний стан:

```powershell
python scripts/corpus_queue.py status --queue .benchmarks/corpus-queue-step03-001/queue.db
```

Окремий локальний модельний запуск доступний через режим run, описаний у
[протоколі](CORPUS_QUEUE_PROTOCOL_V1.md). Він створює власний профіль з
digest моделі та хешем клієнта, не приписує виконання плану unassigned-model.
Зміна digest під час спостереження означає відмову, а не успіх.

Старі кнопки Streamlit і run_single_cycle ще працюють за старою схемою.
Нова точка входу — run_extraction_cycle та scripts/corpus_queue.py run.
З'єднання черги кандидатів із локалізацією й українською деривацією —
наступний етап. Спільний GPU-lock і сумарний токенний бюджет також ще
не реалізовані; поточний ліміт — кількість фрагментів, стеля спроб і timeout
окремого запиту. Наступний предметний дослід — один фрагмент із локальною
моделлю, фіксацією витрат і подальшим запечатуванням результату.
