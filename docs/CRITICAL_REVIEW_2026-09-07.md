# Критичний перегляд: зміст, пропускна здатність та інфраструктура

## Перевірка п'яти зауважень

1. **Пропускна здатність — прийнято.** 84 засвідчення не зросли. Нова
   інфраструктура працює, але місток кандидат → засвідчення → українська
   стаття ще не з'єднаний. Самі 1015 done не вирішать це. Пілот завершив
   1 фрагмент і дав 5 кандидатів, а не 5 готових статей. Точні підрахунки
   рядків коду не повторювалися: вони не змінюють висновку про баланс роботи.
2. **Локальна історія — прийнято з уточненням.** git remote порожній.
   Корпус уже на NAS K:, а Git/пакети — на C:. Потрібні перевірені резервні
   копії, не лише remote: сам remote не зберігає ігноровані .benchmarks.
3. **«Третій шар не запускався» — спростовано.** В обох пакетах є
   seal/independent_recompute.json з PASS, imports_exometric=false, 63 і
   23 артефактами. Обидва знову перераховані з окремими anchors. Причина
   непорозуміння — pending у проміжному журналі bridge. Для наступних
   пакетів додано completion.json; старі пакети не переписуються.
4. **«Словник не запечатаний» — спростовано для поточного зрізу.** Файли
   docs/SCI_FI_LEXICON.md і .json побітово збігаються з export/ у пакеті
   sealed-export-step02-001. Початкова plain receipt збережена як історія,
   поверх неї є сильніша печатка. Прийнята частина: майбутній автоматичний
   експорт ще треба з'єднати із запечатуванням кожного готового випуску.
5. **Сліпе оцінювання недоопрацьоване — прийнято.** Додано ролі, чотири
   шкали 0–3, NA, калібрування, первісні незалежні оцінки, узгодженість і
   арбітраж. Людські оцінювачі ще не призначені; модель їх не замінює.

## Фактична інфраструктура

Read-only огляд двома допоміжними агентами та локальна перевірка пілота:
- RTX3090 24 GiB, i9-12900K, 64 GiB RAM. На одному GPU плануємо один
  генеративний воркер; CPU/мережеві задачі можуть працювати паралельно.
- K: = SMB \\NAS7D999B\Public\antigravity_stack, ≈1.08 TB вільно.
  Для служб використовувати UNC, бо mapping літери залежить від сесії.
- C: NVMe ≈611 GB вільно; D: інший NVMe ≈364 GB; F: окремий SATA
  ≈1.78 TB. NAS snapshots/RAID/зовнішній backup не перевірені.
- MinIO /data прив'язаний до C:/ai_server/minio_data, отже не окрема
  фізична резервна копія. Допоміжний контейнер minio-health unhealthy.
- orcestr-worker та recessive-agent працюють, але факт існування процесу
  не підтверджує виконання бібліографічних задач. Recessive agent — heartbeat.
- run_backup_job.ps1 у Orcestr створює MOCK DATA. Його SUCCESS не є
  доказом резервування цього проєкту. Чужі backup/restore скрипти не запускали.

## Сенсоринг та агенти

Наявні research.mjs/scrape-web.mjs у poket працюють із магазинами
застосунків та ecommerce сайтами. analyze.mjs викликає локальну Ollama.
run_gpu_inference_stage.py у Orcestr придатний як wrapper телеметрії.
Overnight block має lease, retry й stop-механізми, але сам не виконує fetch.
external_autoresearch_adapter.py імпортує training TSV з val_bpb, не шукає
літературу; його евристичний confidence не переносимо на наукові твердження.

Готових бібліографічних адаптерів не знайдено у перевірених Orcestr/src,
Orcestr/scripts та poket/tools. Це обмежений огляд, не твердження про всі диски.
Моя попередня оцінка готовності Orcestr як літературного сенсора була надмірною.

Практична схема: звичайні CPU/HTTP воркери → знімки джерел із provenance
→ черга нових/змінених записів → один локальний GPU-worker → локалізація
→ редакторська черга → версійний запечатаний словник. Джерела та API
добираються й перевіряються окремо. Спершу опрацьовуємо вже наявний корпус,
щоб інтернет-сенсоринг не збільшував лише backlog.

Допоміжні Codex-агенти доречні для обмежених оглядів, розробки адаптерів
і складних винятків. Їх робота не є безкоштовним локальним inference;
постійний сенсоринг плануємо звичайними воркерами, а не дорогими діалогами.
Сесійні агенти не є встановленою фоновою службою після завершення задачі.
