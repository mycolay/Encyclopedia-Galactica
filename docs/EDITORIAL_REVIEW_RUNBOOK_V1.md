# Редакторська процедура: готові форми, оцінювання ще не почалось

Основна рубрика й правила узгодженості: BATCH_AND_EDITORIAL_PROTOCOL_V1.md.
Перевірка заповнених форм і розрахунок узгодженості реалізовані у
scripts/score_editorial_review.py; порядок запуску: IMPLEMENTATION_STEP_10.md.
Генератор: `python scripts/prepare_editorial_review.py --output <новий_каталог>`.
Форми поточного зрізу: .benchmarks/editorial-step09-001/reviewer-1/ratings.json
та reviewer-2/ratings.json. Ключ відповідності зберігає координатор окремо.
Це підготовлені пакети; жодному рецензенту вони ще не надіслані.

1. Призначити двох різних людей і записати компетенції, досвід та конфлікти
   у метаданих форм; щонайменше один має філологічний/перекладацький досвід.
2. Видати кожному лише його папку й спільну рубрику. Не давати чужих оцінок
   та coordinator-key.json. Координатор, який бачив ключ, не є засліпленим.
3. На десяти calibration-записах перевірити достатність контекстів,
   обговорити шкали, зафіксувати версію рубрики. Решта 37 — development_review.
   Це вже оприлюднені матеріали, тому вони не є незалежним сліпим тестом.
4. Для кожного запису спочатку context_sufficient і relevance
   (include/exclude/uncertain) з поясненням. Якщо контекст недостатній,
   запросити ширший оригінальний уривок, оцінки залишити null із na_reasons.
   Доступні уривки короткі й не гарантують достатності.
5. Незалежно заповнити чотири шкали 0–3; null без причини означає незаповнену
   форму, а не NA або нуль. Упізнання походження позначити recognized_provenance.
6. До обговорення зберегти незмінні первісні оцінки. Узгодженість рахувати
   окремо для кожної шкали за основним протоколом; даних зараз для цього немає.
7. Відправляти на арбітраж різницю >=2, семантику 0–1, NA чи суперечність
   оригіналу. Рішення третього оцінювача зберігати окремо. Автозатвердження немає.

Реальний сліпий порівняльний експеримент потребує нових, раніше не показаних
оцінювачам прикладів. Приховування ID саме по собі цього не забезпечує.

## Запобігання новому боргу

run_batch.py більше не генерує чернетки для перших 16 локалізованих слів.
Деривація вимагає --relevance-decisions з JSON-мапою evidence_key → рішення.
Ключ обчислює modules.lexicography.relevance.evidence_key: твір, хеш оригіналу,
назва та хеш контекстного вікна. Include має містити reviewer_role=human,
reviewer, rationale, reviewed_at. Без рішення всі записи залишаються на розгляді.
Копія реєстру й його хеш фіксуються перед запуском; сам файл не посвідчує
особу, це відповідальність координатора. Асистент не заповнює його від імені людини.

Стеля 16 застосовується лише після відбору. Старі чернетки не вилучаються.
Окремий виконавець деривації накопиченого backlog ще не реалізований:
цей gate зупиняє нове автоматичне накопичення, а не ліквідує старий борг.
Профіль екстракції не змінено; нова derivation_policy записується в контракт.
