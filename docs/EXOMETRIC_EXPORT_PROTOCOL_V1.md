# Exometric для експорту Космослова — протокол v1

Мета: запечатати наявний експорт без зміни робочої БД й сусідніх проєктів.
Це інфраструктурний дослід цілісності. Наукової правильності статей,
незалежності людського аудиту чи довіреної часової позначки він не встановлює.

## Зафіксований метод

Використовуємо byte-exact копії lineage.py з Orcestr та bridge/independent
з Manifold. Очікувані SHA-256 записані в modules/audit/exometric.py.
Файл із невідповідним хешем не виконується. Bridge і незалежний перевіряльник
запускаються окремими процесами. Наявні реалізації не редагуються.

Новий каталог пакета створюється з exist_ok=False. Старі прогони й anchors
не перезаписуються. Частково створений пакет після відмови не є готовим:
відсутність anchor означає, що фінальна перевірка не завершена.

Пакет містить експорт Markdown/JSON, snapshot.db, первісну квитанцію,
файли виконавця, інструменти Exometric/Manifold, source_map і тексти з
картами зон для всіх цитат, успішно перевірених під час експорту.
Вхідні файли звіряються з первісною квитанцією; текст звіряється з його
хешем, а цитата — з точним байтовим діапазоном. Карти зон фіксуються на час
запечатування, їхня прив'язка до тексту та включення діапазону в body
перевіряються повторно. Первісний експорт не фіксував хешів самих карт.

Межі: захищаються лише файли, перелічені в manifest. Bridge config і
діагностичні звіти створюються поза цим списком. Перевіряльник перераховує
вміст, не покладається на збережений незалежний звіт. Джерела у corpus/
дозволяють перевіряти цілісність перенесеного пакета без диска K:;
повторний запуск старого експорту зі snapshot.db потребує адаптації шляхів.

## Передбачення та тести до предметного прогону

Чистий і перенесений пакет мають пройти незалежний перерахунок.
Зміна байта, перестановка manifest, самосумісне обрізання його хвоста,
хибний anchor і підміна перевіряльника мають завершитися відмовою.
Повторний запуск у той самий пакет має відмовити без перезапису.
Перевірки в tests/test_exometric_export.py використовують тимчасові фікстури.

## Anchor та аудитор

Anchor створюється тільки після незалежного перерахунку, поза пакетом.
Містить SHA-256 самого manifest, head_chain_hash та кількість артефактів.
Хеш manifest додатково прив'язує імена, шляхи та порядок записів.
Кожна перевірка вимагає переданого anchor й порівнює обидва хеші.
Це закриває самосумісне обрізання лише відносно збереженого оригінального
anchor. Заміна пакета разом із його anchor не виявляється без окремої
довіреної копії останнього.

Виконавець зберігає anchor у Git окремим комітом після прогону.
Аудитору передається файл для власного збереження; до отримання його
підтвердження зовнішнє збереження та людський аудит мають статус pending.
Локальний Git не є незалежним зовнішнім сховищем чи довіреним годинником.

## Команди

`python scripts/audit_export.py seal --run <export-run> --bundle <new-bundle> --anchor <new-anchor.json>`

`python scripts/audit_export.py verify --bundle <bundle> --anchor <retained-anchor.json>`

Бюджет: один предметний пакет, без LLM, GPU, мережі та автоматичних
перезапусків. Кожен subprocess обмежений 60 секундами. Успіх — лише
підтверджена цілісність пакета щодо переданого anchor.
